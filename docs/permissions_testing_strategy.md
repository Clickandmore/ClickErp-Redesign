# خطة اختبار صلاحيات النظام

الغرض من هذه الخطة هو اختبار الصلاحيات بطريقة ثابتة وقابلة للتكرار، خصوصا صفحة:

`/dash/perms/1`

## 1. فحص الربط بين المسارات والصلاحيات

شغل التقرير العام:

```bash
php artisan permissions:audit --module=all
```

وشغل تقرير كل نظام على حدة:

```bash
php artisan permissions:audit --module=ingaz
php artisan permissions:audit --module=hr
php artisan permissions:audit --module=finance
php artisan permissions:audit --module=zatca
```

معنى أهم المؤشرات:

- `الصلاحيات المسجلة في قاعدة البيانات`: كل الصلاحيات التي تظهر في صفحة إدارة الصلاحيات.
- `المسارات المحمية بصلاحيات`: المسارات التي عليها Middleware صلاحيات فعلي.
- `الصلاحيات المطلوبة فعلياً`: الصلاحيات التي يطلبها الكود عند الدخول للمسارات.
- `صلاحيات مطلوبة وغير موجودة`: خطر مباشر، لأن هناك مسارات تطلب صلاحيات غير مسجلة.
- `صلاحيات مسجلة وغير مستخدمة مباشرة`: صلاحيات تظهر في صفحة الصلاحيات لكنها لا تحمي مسارا بشكل مباشر.

## 2. فحص المسارات الإدارية غير المحمية

```bash
php artisan permissions:audit --module=all --show-unprotected
```

أي مسار يظهر هنا يجب مراجعته:

- إذا كان مسارا عاما أو داخليا لا يحتاج صلاحية، يوثق السبب.
- إذا كان شاشة إدارية، يضاف له Middleware صلاحيات.
- إذا كان تابعا لحزمة مثل CRM أو Employee portal، يضاف له نظام ربط واضح مثل HR وFinance.

## 3. فحص الصلاحيات التي تظهر فقط في الصفحة

```bash
php artisan permissions:audit --module=all --show-unused
```

لا يعني كل عنصر هنا أنه خطأ. بعض الصلاحيات تستخدم في القائمة الجانبية أو أزرار داخل Blade، لكن يجب تصنيفها:

- صلاحية تحمي زر فقط: مقبولة إذا كان المسار الخلفي محميا أيضا.
- صلاحية قديمة: تزال بعد التأكد من عدم استخدامها.
- صلاحية ناقصة الربط: تربط بمسار أو Middleware مناسب.

## 4. اختبار يدوي سريع من صفحة `/dash/perms/1`

استخدم دور اختبار منفصل، ولا تختبر بدور المطور أو Administrator.

لكل قسم مهم:

1. ألغ كل صلاحيات القسم واحفظ.
2. سجل دخول بمستخدم على هذا الدور.
3. تأكد أن القسم اختفى من القائمة الجانبية.
4. افتح رابط القسم مباشرة من المتصفح وتأكد أن النتيجة 403.
5. فعّل صلاحية `view` فقط وتأكد أن صفحة العرض تعمل وأن الإنشاء/التعديل لا يعملان.
6. فعّل `create` أو `edit` أو `delete` كل واحدة منفصلة وتأكد أن السلوك مطابق.

## 5. معيار القبول

لا تعتبر الصلاحيات جاهزة إلا إذا تحقق التالي:

- لا توجد `صلاحيات مطلوبة وغير موجودة` في التقرير.
- لا توجد شاشة إدارية مهمة ضمن `--show-unprotected`.
- الروابط المباشرة ممنوعة عند غياب الصلاحية، وليس فقط مخفية من القائمة.
- كل صلاحية في صفحة `/dash/perms/1` إما تحمي مسارا، أو تحمي زر/إجراء موثق، أو تزال.
