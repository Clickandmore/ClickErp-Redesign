🧪 سيناريوهات الاختبار

السيناريو 1 — Super Admin (مشرف)

تسجيل الدخول

http://127.0.0.1:8000/dashboard/login

سجّل بحساب مشرف.

افتح أي موديل (مثلاً: الطلبات)

http://127.0.0.1:8000/admin/ingaz/orders

تحقق من فلتر الفروع

المفروض يظهر dropdown لاختيار الفرع في أعلى الصفحة ويعرض كل الفروع.

تحقق من البيانات

بيانات كل الفروع تظهر بدون قيود. يقدر يفلتر بالفرع اللي يريده.

النتيجة المتوقعة للـ Super Admin

يشوف كل البيانات من كل الفروع، مع فلتر اختياري.

✅ يجب أن يمر

السيناريو 2 — موظف فرع الاختبار (branch2_test)

تسجيل الدخول

http://127.0.0.1:8000/dashboard/login

اسم المستخدم: branch2_test — كلمة السر المعينة له.

تحقق من الـ Dashboard

المفروض يفتح لوحة التحكم الرئيسية بدون إعادة توجيه لـ agent.

افتح الطلبات

http://127.0.0.1:8000/admin/ingaz/orders

المفروض لا يظهر dropdown الفروع ويعرض فقط طلبات فرع الاختبار.

حاول الدخول على بيانات الفرع الرئيسي مباشرة

لو عندك record id = X ينتمي للفرع الرئيسي، حاول تفتحه:

http://127.0.0.1:8000/admin/ingaz/orders/X/edit

المفروض يرجع 403 Forbidden أو يحوله لصفحة ليس لديه صلاحية.

تحقق من صفحة إدارة الفروع

http://127.0.0.1:8000/admin/ingaz/branches

إذا كان عنده صلاحية فقط يظهر له فرعه، وإذا لم يكن له صلاحية يظهر 403.

النتيجة المتوقعة — بيانات الفرع نفسه

يشوف فقط بيانات فرع الاختبار، بدون فلتر فروع.

✅ يجب أن يمر

النتيجة المتوقعة — بيانات فرع آخر (URL مباشر)

لا يستطيع رؤية أو تعديل بيانات الفرع الرئيسي حتى بالـ URL المباشر.

🚫 يجب أن يُرفض (403)

السيناريو 3 — إنشاء فرع جديد واختباره

سجّل دخول كـ Super Admin وأنشئ فرع جديد

http://127.0.0.1:8000/admin/ingaz/branches

اضغط "فرع جديد" واملأ البيانات (الاسم بالعربي مطلوب).

من صفحة الأدمنز أنشئ أدمن جديد

http://127.0.0.1:8000/dashboard/admins

أو عدّل أدمن موجود وعيّن له الفرع الجديد من الـ actions ← تغيير الفرع.

سجّل دخول بالأدمن الجديد وتحقق

يجب أن يرى فقط بيانات الفرع الجديد.

✅ قائمة الاختبار اليدوي
  • تسجيل دخول Super Admin يفتح لوحة التحكم بدون مشاكل
  • Super Admin يرى فلتر الفروع في صفحة الطلبات
  • Super Admin يرى بيانات كل الفروع
  • تسجيل دخول branch2_test يفتح لوحة التحكم (مش agent dashboard)
  • branch2_test لا يرى فلتر الفروع في صفحة الطلبات
  • branch2_test يرى فقط بيانات فرع الاختبار
  • branch2_test يحصل على 403 عند محاولة فتح record من فرع آخر بـ URL مباشر
  • صفحة الفروع تظهر اسم الموظف المعين للفرع في عمود "مدير الفرع"
  • popup تعيين المسؤول يعمل ويحفظ بشكل صحيح
  • popup إدارة الموظفين (رقم الموظفين) يفتح ويعرض القائمة
  • إضافة أدمن لفرع من popup الموظفين يعمل
  • إزالة أدمن من فرع تعمل
  • إنشاء فرع جديد وتعيين أدمن له يعمل
  • الأدمن المعين للفرع الجديد يرى فقط بياناته عند الدخول

🗄️ قاعدة البيانات — Migrations

  • database/migrations/..._add_branch_id_to_admins_table.php migration
    أضاف عمود branch_id (FK) لجدول admins — يربط كل أدمن بفرع معين.
  • database/migrations/..._add_is_branch_manager_to_admins_table.php migration
    أضاف عمود is_branch_manager boolean لجدول admins — يحدد المسؤول عن الفرع.
  • database/migrations/..._backfill_admins_branch_id_to_main_branch.php migration
    يحدّث كل الأدمنز اللي ليس لهم branch_id ويعينهم للفرع الرئيسي تلقائياً — مستثنياً الـ external office agents.

🏗️ Models

  • app/Models/Branch.php تعديل
    أضيفت relationships:
    • manager() — hasOne Admin حيث branch_id = هذا الفرع + admin_type real admin (يعرض الموظف المسؤول تلقائياً)
    • admins() — hasMany الأدمنز الحقيقيين في هذا الفرع (مستثنياً الـ agents)
  • app/Models/auth/Admin.php تعديل
    أضيف cast لـ is_branch_manager كـ boolean.

⚙️ Services

  • app/Services/BranchAccessService.php جديد
    الـ service الأساسية لنظام عزل الفروع. تحتوي على:
    • adminBranchId() — يرجع branch_id للأدمن المسجل (null للـ super_admin)
    • applyRequestBranchFilter($query, $branchColumn) — يطبق فلتر الفرع على أي query تلقائياً
    • assertCanAccessBranchModel($model) — يتحقق إن الأدمن يقدر يوصل لهذا الـ record، يرمي 403 لو لا

💡 قرارات تصميمية مهمة

  • is_branch_manager vs manager_id: تم اختيار boolean is_branch_manager على جدول admins بدل عمود manager_id على جدول branches — لأنه يدعم تعدد المديرين مستقبلاً بدون تغيير الـ schema.
  • عرض المسؤول في جدول الفروع: العمود يعرض أول أدمن حقيقي معين للفرع (عبر branch_id) تلقائياً بدون حاجة لخطوة "تعيين مدير" منفصلة — من ربط الأدمن بالفرع من صفحة الأدمنز يكفي.
  • External Office Agents: الـ agents (admin_type = 0 أو لديهم سجل في admin_offices) مستثنيون من نظام الفروع — لهم مسار منفصل (/agent/dashboard) ولا يُعينون للفروع.
  • الطلبات المالية (financial_requests): جدول financial_requests لا يحتوي على branch_id — يحتاج migration مستقبلاً لإضافة عزل الفروع عليه.
