# استرداد تكلفة الوكيل من الإيواء

التنفيذ في فرع `feature/shelter-ledger-accounting`، بتاريخ 2026-09-13. يوسّع القيد 18 بالسماح بمطالبة المكتب بتكلفته الأصلية قبل الترحيل، دون تغيير حالة العاملة. الإعاشة لا تدخل في مبلغ الاسترداد. هذه المطالبة ليست سند قبض ولا إيراد استرداد مبيعات.

## الدورة الجديدة

1. قيد تكلفة المورد يثبت تكلفة الوكيل وحساب المكتب الأصلي.
2. الإرجاع داخل الضمان (المعالجة الافتراضية) ينشئ S1: مدين أصل الإيواء / دائن مردودات التكلفة، مع مستندات العميل المستقلة.
3. من الإيواء ← عرض التفاصيل ← «استرداد تكلفة الوكيل»، يعرض النظام مرجع التكلفة والمكتب والمبلغ المتبقي. يحدد المحاسب التاريخ والسبب ومرجع المطالبة. يسترد كامل المتبقي من مصدر التكلفة المختار، دون مبلغ حر يخلط الإعاشة بالتكلفة.
4. القيد: مدين حساب المكتب الأصلي / دائن أصل الإيواء على مركز تكلفة العاملة. يثبت مبلغاً على كشف المكتب (أو يخفض مستحقاته بحسب رصيده)؛ لا يسجل تحصيلاً نقدياً.
5. الإعاشة تستمر حسب إعداد الرسملة. نقل الخدمات وإعادة البيع يستخدمان الرصيد المتبقي، وفشل التجربة يعيد ما خرج فقط.
6. عند الترحيل تُصفّى تكلفة الوكيل غير المستردة على المكتب أو الخسائر حسب إعدادها، وتُصفّى الإعاشة بصورة مستقلة. افتراضي الإعاشة الجديد هو خسائر الإيواء. تحميل الإعاشة على المكتب خيار مستقل لا يعمل دون مكتب أصلي وحيد مثبت.

مثال: تكلفة وكيل 10,500 + إعاشة مرسملة 750 = رصيد 11,250. الاسترداد يُدين المكتب 10,500 ويُدائن أصل الإيواء 10,500، فيبقى 750. الترحيل اللاحق يحمّل الخسائر 750 مقابل إقفال الأصل، ولا يعيد مطالبة المكتب بالتكلفة. إذا كان عقد نقل الخدمات 20,500، يصبح مبلغ إيراد النقل وفق طريقة النظام الحالية 19,750 بدلاً من 9,250، لأن تكلفة الوكيل المستردة لم تعد ضمن تكلفة التجربة. مستندات العميل والضريبة وخصم مدة البقاء لا تتغير بهذا الإجراء.

## الضوابط

- صلاحيتان مستقلتان، لا تُمنحان تلقائياً لكل أصحاب إدارة الإيواء: `shelter_agent_cost_recovery` و`shelter_agent_cost_recovery_reverse`. يجب أيضاً امتلاك صلاحية عرض تفاصيل الإيواء للوصول للنموذج.
- حساب المكتب يُستخرج من الطرف الدائن بقيد تكلفة المورد الأصلي، وليس من قيد S1 (فهو لا يحتوي حساب المكتب) ولا من المكتب الحالي للعاملة. يُحفظ المرجع والحساب على مصدر التكلفة.
- يلزم قيد استلام مثبت وحساب أصل ومورد موثقين. وجود العاملة بالإيواء أو قيمة تكلفة في العقد وحدهما لا يسمحان بالاسترداد.
- عكس المورد السابق، بما فيه وضع «عند الفاتورة»، يمنع الاسترداد المكرر. وجود استرداد نشط يمنع عكس نفس قيد المورد لاحقاً.
- تتبع حركة التكلفة يشمل البيع والتصفية والترحيل والتجربة وعودتها؛ جمع الاستلام ناقص الاسترداد وحده غير كافٍ.
- الطلب المكرر بنفس المرجع يعيد العملية نفسها. طلب جديد بعد استرداد المبلغ يُرفض. القيد والحركة والمستند تُحفظ في معاملة واحدة مع قفل العاملة، مشترك مع حركات الدفتر الأخرى.
- الاسترداد لعقد الاستقدام الأصلي وهو داخل الإيواء، والقيود الآلية مفعلة، والتاريخ لا يسبق آخر قيد إيواء ولا يكون مستقبلياً.
- العكس يحتاج سبباً وصلاحية منفصلة. يُرفض بعد حركة خروج لاحقة (حتى تجربة فشلت لاحقاً، أو بيع برصيد صفر). المنع يحمي القيود اللاحقة؛ عكس الاسترداد في ذاته يزيد الأصل ولا يسبب رصيداً سالباً.
- حالات المصدر غير المكتمل، والتسوية غير المصنفة، والخروج التاريخي الجزئي غير القابل للفصل، تُعرض للمراجعة ويُرفض التنفيذ الآلي.

## معالجة السابق

لا يُنفّذ استرداد على العاملات القديمات تلقائياً، ولا تُغيّر القيود المنشورة، ولا يُعاد تصنيف مصروف إعاشة تاريخي بناءً على إعداد الرسملة الحالي.

1. خذ نسخة احتياطية، وأوقف إدخال الحركات أثناء بناء دفتر قديم لضمان ترتيب ومطابقة المصادر.
2. شغّل المعاينة:

```bash
php artisan finance:shelter-ledger-reconcile
```

3. بعد مطابقة القيود، ابنِ حركات الدفتر المثبتة فقط:

```bash
php artisan finance:shelter-ledger-reconcile --apply
php artisan finance:shelter-agent-cost-audit
```

يمكن إضافة `--maid=123` لكلا الأمرين لحصر العمل على عاملة. أمر `--apply` وحده لم يعد ينشئ قيود ترحيل.

4. راجع مع المحاسب الحالات التالية:

| الحالة القديمة | المعالجة |
|---|---|
| قيد 9/S1 مثبت وقيد المورد الأصلي موجود | يبنى المصدر دون إنشاء قيد جديد، وتتاح المطالبة بعد مراجعة كشف المكتب. |
| إعاشة مدينة على أصل الإيواء بمركز تكلفة مطابق | تبنى حركة إعاشة بالمبلغ المثبت حتى لو تغير الإعداد الحالي. |
| إعاشة على مصروف فترة | لا تُرسمل تلقائياً. إن تقررت إعادة التصنيف، تحتاج مستند تسوية محاسبي مستقل ومطابقة الدفتر. |
| تكلفة مكتوبة بالعقد دون قيد S1 | يظهر عدم وجود تكلفة متاحة؛ يلزم استكمال المستندات والقيد الأصلي بمعالجته المعتمدة، ولا يُنشأ رصيد افتراضي. |
| عكس سابق لقيد المورد | تظهر التسوية السابقة؛ لا استرداد جديد. |
| مطالبة يدوية أو تحصيل سابق على كشف المكتب | تُطابق أولاً مع مستنداتها؛ لا تضغط الاسترداد مجدداً. هذه العمليات لا تُكتشف آلياً إذا لم تحمل روابط النظام. |
| خروج جزئي أو تسوية قديمة غير مصنفة | يتوقف الفصل الآلي؛ يلزم تحديد أصل التكلفة ومكونات الحركات وتصحيح الربط تحت مراجعة المحاسب قبل إتاحة الاسترداد. |
| دفتر بُني سابقاً خطأً من إعاشة مصروف فترة | الأمر لا يمسح الحركة الموجودة أو يصححها تلقائياً؛ يلزم مطابقة وإصلاح الدفتر مع القيود قبل التشغيل. |
| ترحيل قديم مكتمل بلا قيد | يُراجع الرصيد ومكوناته وحساب الخسائر؛ إنشاء القيد يحتاج الخيار الصريح أدناه. |

```bash
php artisan finance:shelter-ledger-reconcile --maid=123 --post-missing-deportations
php artisan finance:shelter-ledger-reconcile --maid=123 --apply --post-missing-deportations
```

قيود استكمال الترحيل تُنشأ بتاريخ التنفيذ ضمن سنة مالية مفتوحة، دون تغيير تاريخ الترحيل التشغيلي. معاينة الترحيل تعرض الرصيد المتوقع؛ التنفيذ يعيد التحقق من المكونات والحسابات وقد يرفض الحالة غير المكتملة. التقرير لا يُعد بديلاً عن مطابقة كشف المكتب.

## المطلوب من المحاسب قبل الاستخدام

- تحديد حساب خسائر الإيواء الطرفي في «حسابات الإيواء والترحيل». الإعاشة ستُحمّل عليه افتراضياً عند الترحيل؛ إن لم يُحدد يُرفض ترحيل أي رصيد إعاشة.
- مراجعة ربط أصل الإيواء ومردودات التكلفة لكل جنسية، وحساب إيواء التجربة، وحساب المكتب بقيد المورد الأصلي.
- تحديد إن كانت الإعاشة ستبقى مصروف فترة أم أصلًا مرسملًا؛ التغيير يخص الحركات الجديدة.
- توثيق أساس مطالبة المكتب ومرجع الاتفاق والتاريخ ومطابقة المبلغ مع كشفه؛ ثم استخدام الاسترداد للعاملة المختارة فقط.
- عند وصول المبلغ: تسجيل سند قبض على حساب المكتب، أو تسجيل التسوية المعتمدة مع مستحقاته. لا إعادة تسجيله كإيراد استرداد مبيعات.
- تسوية التحصيل أو المقاصة المرتبطة بالمطالبة قبل عكسها. التحصيل العام على كشف المكتب ليس مربوطاً آلياً بهذا المستند.
- مراجعة أثر انخفاض تكلفة التجربة على إيراد نقل الخدمات وفق طريقة النظام الحالية.

## الترقية والتحقق

يلزم تطبيق migration دفتر الإيواء أولاً إن لم يكن مطبقاً، ثم:

```bash
php artisan migrate --path=database/migrations/2026_09_13_120000_add_shelter_agent_cost_recoveries.php --force
php artisan optimize:clear
```

على بيئة الاختبار فقط، تُطبّق الهجرة على `rafdain_testing`. أمر `test:db-provision` يعيد إنشاء قاعدة الاختبار، وليس خطوة نشر لقاعدة التشغيل.

اختبارات `ShelterCostLedgerTest` تغطي الفصل عند الترحيل، الاسترداد ثم الترحيل/التجربة، منع التكرار، الحساب الأصلي، العكس، البيع برصيد صفر، عكس المورد، الصلاحيات، ومنع رسملة مصروف الفترة القديم تلقائياً.
