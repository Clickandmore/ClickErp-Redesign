# قواعد إعادة التصميم والتسليم

## ما يمكن تعديله

- HTML داخل قوالب Blade وترتيب عناصر الواجهة.
- أصناف CSS والتباعد والألوان والخطوط والاستجابة للجوال.
- المكوّنات البصرية مثل الجداول والبطاقات والنوافذ والحالات الفارغة.
- JavaScript الخاص بالتفاعل البصري، مع الحفاظ على عقود الطلبات الحالية.

## ما يجب الحفاظ عليه

- تعبيرات Blade مثل `{{ ... }}` و`{!! ... !!}` و`@foreach` و`@if`.
- أسماء حقول النماذج وقيمها وخصائص `data-*` والمعرّفات التي يستخدمها JavaScript.
- أسماء المسارات داخل `route(...)`، وعناوين الطلبات وطرق `GET/POST`.
- توجيه RTL، مع اختبار LTR أيضاً عندما تكون للصفحة ترجمة إنجليزية.
- شروط الصلاحيات وإظهار الأزرار، مثل `@permission` و`@can` وما يشابهها.
- مواضع `@yield` و`@stack` و`@push` في القوالب العامة.

لا تُستبدل البيانات الديناميكية بنصوص ثابتة داخل ملفات التسليم النهائية. يمكن استخدام بيانات وهمية في نموذج منفصل للمعاينة فقط.

## نقطة البداية للتصميم العام

- الهيكل: `source/resources/views/admin/layout/indexs/index.blade.php`
- الشريط الجانبي: `source/resources/views/admin/layout/inc/sidebar.blade.php`
- الرأس: `source/resources/views/admin/layout/inc/header.blade.php`
- ملفات CSS العامة: `public/admin/custom/` و`public/admin/assets/css/`
- ملفات JavaScript العامة: `public/admin/assets/js/`

## المطلوب مع كل مجموعة شاشات

- صور قبل/بعد لمقاسات سطح المكتب والجوال.
- قائمة بالملفات المعدّلة.
- توضيح الحالات التي تمت تغطيتها.
- ملاحظات الدمج إذا تغير DOM يعتمد عليه JavaScript.
- عدم إضافة مكتبة خارجية جديدة إلا مع توضيح سببها وحجمها وترخيصها.

## تنبيه الخصوصية

لا تستخدم لقطات شاشة تحتوي على أسماء عملاء أو أرقام هوية أو هواتف أو عقود حقيقية. استخدم بيانات وهمية بالكامل في التصميم والمعاينة.
