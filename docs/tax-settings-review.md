# إصلاح واختبار إعدادات الضريبة قبل الرفع

آخر تحقق: 2026-09-06.

## ما أُصلح

- اختيار تعريف ضريبة افتراضي من الإعدادات المالية يرفض النسبة صفر أو خارج 1–100، بالإضافة إلى اشتراط حساب طرفي بالطبيعة المناسبة. التعريف الصفري العادي يظل مسموحًا، لكنه لا يصلح افتراضيًا.
- إعادة إرسال اختيار ضريبة فارغ لا تمحو الإعدادات القائمة. الحفظ داخل معاملة.
- سجل الحسابات يحفظ الحساب قبل وبعد تغيير اختيار الضريبة أو تعديل تعريفها عبر الخدمات، ويُقرأ عند تفسير تسويات التأجير القديمة. السجل داخل `fn_confirm_settings` بمفاتيح `tax_history_<side>_<accountId>`، وليس مصدرًا لترحيل العمليات الجديدة. لا يستعيد تلقائيًا حسابات تاريخية اختفت قبل تفعيل السجل أو تغييرات مباشرة عبر SQL؛ هذه تحتاج مراجعة مستقلة.
- الترحيل يحافظ على الحساب القديم الصالح عندما يوجد، وعلى نسبة التعريف المختار. يعيد استخدام تعريف يطابق **الحساب والنسبة**، ويحافظ على اختيار صحيح قائم. عند غياب نسبة مختارة لا يقبل إلا نسبة وحيدة غير ملتبسة؛ يتوقف عند التعدد أو الغياب أو الصفر أو الحساب غير الصالح، ويعيد كامل تغييرات الجانبين. لا يفترض نسبة 15 ولا أرقام حسابات ثابتة ولا مستخدمًا إداريًا برقم 1.
- الشركة غير المضبوطة بالكامل تبقى دون تخمين، ويبلغ أمر التدقيق عن الحاجة لضبطها.
- أمر `finance:tax-accounts-audit` للقراءة فقط. أزيل خيار `--pin` وتخمين الأكواد والأسماء. نجاحه يثبت توافق الإعدادات الحالية فقط، وليس صحة التاريخ.
- حماية حذف الضريبة تشمل الآن استخدامها في بيع الأصول `fn_principle_sales.tax_setting_id` أيضًا.

## نتائج الاختبار

- `TaxAccountResolverTest`: 22 اختبارًا، 55 تحققًا. تشمل الصفر، اختلاف الأشجار وأرقام المستخدمين، غموض النسبة والتراجع الكامل، الإعداد الصحيح أو المفقود، وتغييرات الحسابات المتتالية.
- حساب الفواتير والتأجير ومطابقة التسويات: 23 اختبارًا، 90 تحققًا.
- المجموع: **45 اختبارًا، 145 تحققًا**.
- `git diff --check` ناجح.

### MySQL من بيانات فعلية

نُسخت جداول `admins`, `fn_accounts`, `fn_tax_settings`, `fn_confirm_settings` من `rafdain_test` إلى قاعدة مؤقتة مستقلة باسم مولّد عشوائيًا. أُضيفت العلاقات المرجعية اللازمة التي لا ينسخها `CREATE TABLE LIKE`.

نُفذ الترحيل مرتين على القاعدة المؤقتة:

- الإيرادات بقيت 114، بنسبة 15%.
- المصروفات بقيت 115، بنسبة 15%.
- لم تتكرر التعريفات أو صفوف الإعدادات عند إعادة التنفيذ.
- تطابقت checksums الجداول الأصلية قبل الاختبار وبعده.
- حُذفت القاعدة المؤقتة بعد انتهاء الاختبار.

سكريبت التحقق في جلسة العمل: `/private/tmp/tax_mysql_isolated_test.php`. اختبار MySQL يخص الترحيل والإعدادات، وليس دورة واجهة كاملة أو نسخة كاملة من كل الموديلات. لم يُشغّل الترحيل على قاعدة العمل الأصلية.

## المطلوب لكل شركة

| حالة الشركة | المطلوب |
|---|---|
| الحساب والتعريف والنسبة متوافقون | احتفاظ بالإعداد الصحيح، ثم اختبار الترحيل دون تغيير النتائج |
| حساب قديم صالح ولا تعريف افتراضي | ربط تعريف بنفس الحساب والنسبة المؤكدة؛ الترحيل يتوقف إذا تعددت النسب |
| تعارض الحساب القديم والتعريف | مراجعة القيود واعتماد الحساب والنسبة قبل التشغيل؛ الترحيل يحافظ على القديم الصالح ولا يقرر أنه الصحيح تجاريًا |
| إعدادات غير موجودة أو حساب غير صالح | ضبط يدوي من شجرة الشركة؛ لا يُنسخ حساب من شركة أخرى |
| تغيّرات قديمة في حساب الضريبة | مراجعة الحسابات التاريخية غير المسجلة قبل الإصلاح، ومقارنة التقارير والتسويات |

## خطوات التنفيذ

1. خذ نسخة احتياطية قابلة للاستعادة، وأنشئ نسخة اختبار مستقلة من قاعدة الشركة. سجّل حسابي الضريبة ونسبتيهما ومجاميع التقارير قبل التغيير.
2. شغّل التدقيق على نسخة الاختبار:

```bash
php artisan finance:tax-accounts-audit
```

أي نقص أو تعارض يحتاج مراجعة الإعدادات والقيود. لا تعتمد كودًا ثابتًا مثل 1281/1282 أو معرّفات 114/115؛ هذه تخص الشركة المفحوصة فقط.

3. في نسخة الاختبار، بعد حسم الإعدادات، شغّل الترحيل المحدد وحده:

```bash
php artisan migrate --path=packages/finance/database/migrations/2026_09_06_130000_consolidate_tax_account_settings.php
php artisan finance:tax-accounts-audit
```

4. اختبر حفظ إعداد آخر دون تغيير الضريبة، وسند قبض وصرف وفاتورة وتأجير ومساند، وقارن الحساب والنسبة والمبالغ والتقارير والتسويات مع النتائج المتوقعة. اختبارات الحساب الآلية لا تغني عن دورة تشغيل الشركة الفعلية.
5. بعد النجاح، أوقف استقبال العمليات مؤقتًا أثناء نشر الكود وتشغيل الترحيل في الشركة، ثم امسح الكاش واختبر الإعدادات قبل إعادة استقبال العمليات. يمنع ذلك فترة تشغيل بالكود الجديد قبل اكتمال نقل الإعدادات.
6. عند فشل الترحيل لا تتجاوزه ولا تغيّر الحساب عشوائيًا. أصلح سبب الفشل وأعد الاختبار. `down()` لا يعيد اختيار الإعداد السابق؛ الرجوع المعتمد من النسخة الاحتياطية مع الكود السابق.

## حدود قائمة

السندات ما زالت تحفظ الحساب والنسبة والمبلغ المرسلة من نموذج العملية؛ تشديد اشتقاق هذه القيم على الخادم خارج تغييرات هذه الحزمة. بعض معادلات الفواتير والتأجير تستخدم 15% ثابتة. تقرير الإقرار يطبق النسبة الحالية على تجميع تاريخي، وبعض التقارير تختار حسابًا واحدًا؛ لذلك الشركات التي غيرت النسبة أو الحساب عبر الزمن تحتاج مقارنة تاريخية خاصة قبل الاعتماد. لم تُعدّل القيود القديمة تلقائيًا.

تغييرات المشتريات والموردين والضمان الموجودة بالتوازي خارج نطاق هذا التحقق. لا ترفعها ضمن إصلاح الضريبة دون مراجعتها المستقلة.
